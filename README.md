# Tatanka Indicators for Sierra Chart (beta)

Sierra Chart versions of the nine free, open-source Auction Market Theory indicators from [Tatanka Trading](https://tatankatrading.com), built as ACSIL custom studies. The originals for NinjaTrader 8 and TradingView live in [tatanka-indicators](https://github.com/tatankatrading/tatanka-indicators).

> [!WARNING]
> **Beta.** These studies were ported line by line from the NinjaTrader versions and checked against NinjaTrader's own calculations. They build in Sierra Chart 2970 and run on its sample data, but haven't been checked on a live data feed yet. Expect rough edges, especially in see-through shading, the hidden 1-minute and daily charts, and text on high-DPI displays. The NinjaTrader and TradingView versions remain the reference. If something looks wrong, slow or different, please [report it](#report-a-bug).
>
> For education and chart analysis only: no buy or sell signals, not financial advice, no warranty (see the [license](LICENSE)). Futures trading carries substantial risk of loss.

## Install

1. Download the `.cpp` files (green **Code** button → **Download ZIP**, or each file on its own) and copy them into the `ACS_Source` folder in your Sierra Chart folder (usually `C:\SierraChart\ACS_Source`).
2. In Sierra Chart: **Analysis → Build Custom Studies DLL → File → Select Files**, and pick one file.
3. **Build → Remote Build - Standard.** Sierra Chart compiles it on its server, so you don't need Visual Studio. Repeat for each file.
4. On a chart: **Analysis → Studies → Add Custom Study**, open the Tatanka DLL and add the study.

If a build fails, copy all the text in the **Output** area into a [bug report](#report-a-bug).

**Updating:** copy the new `.cpp` files over the old ones and build each one again. On charts that already have the AMT Toolkit, check that **4. Prev Value: Value From Ticks (Sessions)** reads 5 and **11. Profile: Profile From Ticks** reads Yes, and leave the session inputs at their defaults (see [each market's own hours](#amt-toolkit-each-markets-own-hours)).

## Chart setup

- **AMT Toolkit:** a 1 to 30 minute chart, **Session Times** (Chart Settings) covering the full Globex session (17:00-16:00 CT for CME) and **Days to Load** of about 60. For the prior day's value and the profile from every trade, set **Intraday Data Storage Time Unit** to **1 Tick** (Global Settings → Data/Trade Service Settings). Turn alerts on for one chart per symbol, or each alert fires twice.
- **Session Volume Profile:** set **Intraday Data Storage Time Unit** to **1 Tick** (Global Settings → Data/Trade Service Settings) and download tick history.
- **Periodic and Auto Anchored Volume Profiles:** raise **Days to Load** to cover the period (about 400 days for a yearly profile). A 1-minute chart loads fastest.
- **TPO Profile:** for see-through boxes, set **Box Drawing** to Transparent and **Box Transparency (0-100)** to about 75 (TradingView's look).

**Hidden charts are normal.** The AMT Toolkit and the Periodic and Auto Anchored Volume Profiles open a hidden 1-minute chart of the same symbol. The AMT Toolkit, TPO Profile and If/Then open a hidden daily chart. They appear in the **Window** menu: leave them open. Charts of the same symbol share them.

## AMT Toolkit: value and profile from every trade

The study reads every trade from the chart's own tick data (its intraday data file), as NinjaTrader 1.2.4 downloads them:

- **pdPOC, pdVAH and pdVAL** come from every trade of the RTH session at one-tick rows, the way a tick volume profile builds them, for the last **5** sessions (**4. Prev Value: Value From Ticks (Sessions)**, 0 to 20; 0 keeps 1-minute bars). With **11. Profile: Profile Period** on Session and its **Session Time** on the same hours as the prior day's value (08:30-15:00 CT by default, 07:20-12:30 on GC), that day's profile is drawn from the same trades at one-tick rows: its tallest row is pdPOC and its shaded value area ends at pdVAH and pdVAL when the two **Value Area %** inputs match.
- **The current Session or Weekly profile** (the default), its POC and value area and the Developing POC, VAH and VAL lines come from every trade at the Row Scale's rows, from the period's start (**11. Profile: Profile From Ticks**; off keeps 1-minute bars). Monthly and Yearly profiles and older periods use 1-minute bars, as in NinjaTrader. A Session profile loaded over a weekend or a holiday (Monday before the session, say) takes the trades of the session it shows, Friday's, so it matches a chart left running.
- Older days, and any minute or session whose trades are missing or don't add up to its 1-minute bars, use 1-minute bars (each minute's volume spread over its range), as NinjaTrader falls back. So do days stored as records of several trades (older history kept at 1-second storage). A chart bar of the Session or Weekly profile with no minute from trades is built at **Calc Precision**, as older profiles are.
- **Every pd line** (pdHigh, pdLow, pdOpen, pdPOC, pdVAH, pdVAL) switches to the session that just closed at its close (15:00 CT by default: 12:30 on GC, 13:30 on CL), and that session's profile is redrawn from its trades then. From the close to the 17:00 open the new lines start at the close and the chart keeps the old ones over the day before it. Today's 80% Rule, the OPEN row and the day type stay measured against the value in force at today's open.
- As the chart loads, the study reads the tick data from the earliest session it needs (about a week back with the defaults, more with more sessions) before it draws, a slice at a time so the chart stays responsive ("loading chart and secondary history" shows meanwhile). It waits 2 minutes at most, or 1 minute when the current profile doesn't come from ticks (**Profile From Ticks** off, a Monthly or Yearly profile, or no profile), as NinjaTrader waits for its tick downloads. If the tick data isn't all read by then, the chart is drawn anyway and the message log says so: what isn't read yet uses 1-minute bars, and the reading goes on. Live, each trade is read as it comes.
- If the prior day's trades are read only after the chart is drawn (the wait ran out) or after today's session has started (a very large burst), the prior day's value switches to them then, today's 80% Rule starts over from that bar on the tick values and its fill so far is cleared, as in NinjaTrader; an 80% Rule alert already sent stays sent.
- The study tells from the chart's bars whether the tick data's times are chart time or UTC. On a 20- or 30-minute chart one hour from UTC (London in summer, Central Europe in winter) the newest trade fits both, so the bars' opens, closes and volumes decide. A chart at UTC+0 reads the same either way, and the study checks again when its time zone moves off UTC+0. Changing the chart's time zone reads the tick data again.
- If the tick data's times don't match the chart's bars, the message log says so and the study uses 1-minute bars. If the data isn't stored tick by tick, the message log asks for 1 Tick storage. A record Sierra Chart can't read is left out after 3 tries, and the message log says so.
- **Updating from the study's version 1.0.0 or 1.1.0:** on charts that already had the study, check that **4. Prev Value: Value From Ticks (Sessions)** reads 5 and **11. Profile: Profile From Ticks** reads Yes. These two inputs are new, and Sierra Chart may restore the empty values an older chartbook saved in their places (0 and No, which turn the trades off). Set them, or remove the study and add it again.

Other rules from NinjaTrader 1.2.2:

- OVN INVENTORY shows the count at the last overnight bar (the bar before **RTH Open Time**: 08:30 on ES, 07:20 on GC), so it no longer says TRAP after the trap resolved.
- The prior month's value (pmPOC, pmVAH, pmVAL) comes from the month's 1-minute bars at the profile's rows when the chart holds the whole month, so it matches the Monthly profile and its naked POC. Shorter charts use 30-minute bars.
- A line's alert watches only while the line is drawn. The OVN alerts stop with their lines at **Delete OVN Lines At**.
- Poor highs and lows sit at the session's high and low, and a trade one tick beyond repairs them. A single print fills when its price trades from below too.
- Turning off the IB or the OVN High/Low no longer changes the DAY TYPE.
- The prior day's and month's value and the naked POCs use the profile's rows, so on GC the labels match the lines and on CL a naked POC sits on its profile's POC.
- Level zones in ATR % mode use the **Daily ATR Period**, as the dashboard does, and the Zone Entry alert shows the zone's half-width unrounded.
- An RTH Session for VA starting after the regular open (08:30 on ES) decides OPEN, the gap test and the 80% Rule together, from its first bar.

Other rules from NinjaTrader 1.2.3:

- A **Session Time** through midnight (1700-1600, a whole Globex day, or 1700-0830) is one profile from its start, not two split at midnight.
- The DAY TYPE waits for today's IB, whatever **IB Calc Period** is set. Until the IB is complete it measures against the overnight range, and it never says Non-Trend Day before then. Before, an IB to 10:00 said Non-Trend Day from 09:30, and an IB from 09:00 measured 08:30 to 08:59 against yesterday's IB.

## AMT Toolkit: each market's own hours

The session inputs are written for ES's regular hours, 08:30-15:00 CT. With **1. Global: Use Instrument Hours** on (the default), the study moves them to the regular hours of the chart's market, as NinjaTrader 1.2.4 does. A time nearer the open moves with the open, a time nearer the close moves with the close, and the overnight start stays at 17:00. That covers every session input: the IB, the prior day's high, low, open and value, the OVN session and when its lines go, OVN INVENTORY and its settle, the day type, the RTH VWAP, the TPO session and its periods, the late spike, the profile's Session Time (and its Session Duration when that was the session's length), the dashboard's sessions and the alert windows. The RTH open line (dOpen) starts at the market's own open.

| Market | Regular hours (CT) | IB | Close and settle | Minute bars |
| --- | --- | --- | --- | --- |
| ES, NQ, YM, RTY, EMD, NKD and their micros | 08:30-15:00 | 08:30-09:30 | 15:00 | 1, 5, 10, 15 or 30 |
| CL, MCL, QM, NG, RB, HO | 08:00-13:30 | 08:00-09:00 | 13:30 | 1, 5, 10, 15 or 30 |
| GC, MGC | 07:20-12:30 | 07:20-08:20 | 12:30 | 1, 5 or 10 |
| SI, SIL | 07:25-12:25 | 07:25-08:25 | 12:25 | 1 or 5 |
| HG, MHG | 07:10-12:00 | 07:10-08:10 | 12:00 | 1, 5 or 10 |
| PL | 07:20-12:05 | 07:20-08:20 | 12:05 | 1 or 5 |
| PA | 07:30-12:00 | 07:30-08:30 | 12:00 | 1, 5, 10, 15 or 30 |
| ZT, ZF, ZN, TN, ZB, UB, SR3 and the currencies (6E, M6E, 6B, 6J, 6A, 6C, 6S, 6N, 6M) | 07:20-14:00 | 07:20-08:20 | 14:00 | 1, 5 or 10 |

On GC with the defaults: the IB is 07:20-08:20. pdHigh, pdLow, pdOpen, pdPOC, pdVAH and pdVAL come from 07:20-12:30 and switch at 12:30. OVN INVENTORY counts 17:00 to 07:20 against the 12:30 settle. The OVN lines go at 12:30, the late spike is 12:00-12:30 and the RTH VWAP runs 07:20-12:30. The TPO periods behind single prints and poor highs and lows are 07:20-07:50, 07:50-08:20 and so on. A Session profile is 07:20-12:30. On CL the IB is 08:00-09:00, the value and the pd lines come from 08:00-13:30, the settle is the 13:30 close and the late spike is 13:00-13:30. ES, NQ, YM and RTY are the same as before.

- Leave the session inputs at their defaults. They still show ES's times (0830-1500, 08:30); the study moves them.
- An input you typed in the market's own hours moves again: 0720-1230 on GC becomes 06:10-10:00. Retype it in ES's hours: the default if it was gold's version of the default, or 0830-1000 for an IB you typed as 0720-0850.
- An input you changed on purpose moves the same way: an IB Calc Period of 0830-1000 is 07:20-08:50 on GC.
- The study works on the chart's bars, so use a bar size the market's open and close fall on (the last column). On longer bars a time inside a bar moves to the next bar: on a 15 or 30 minute GC chart the IB and the RTH open start at 07:30.
- Off, every input runs as typed on every market, as in the study's 1.2.3. The regular hours then stay 08:30-15:00 too: on GC the settle OVN INVENTORY compares against is the 15:00 close, and the RTH open and the day type stay on 08:30-15:00.
- **15. Inventory: Globex Start Time** doesn't move (NinjaTrader's Globex Start doesn't either), and a trading day still starts at 17:00 CT.

**Which market.** NinjaTrader looks the hours up by the instrument's root. Sierra Chart has no root field, so the study reads the root from the chart's symbol:

- Sierra Chart's own symbols and the usual feeds: `GCZ26_FUT_COMEX`, `GCZ6`, `GCZ26-COMEX`, `GCZ6.COMEX` and `GC#` are GC; `MGCZ26_FUT_COMEX` is MGC (gold's hours). The month code and year are dropped.
- CQG's symbols (`F.US.GCEZ26`) use CQG's names: a trailing E is dropped (GCE is GC, CLE is CL, SIE is SI, MCLE is MCL), CPE is HG, NQM is QM, EP is ES, ENQ is NQ, TYA is ZN, USA is ZB, FVA is ZF, TUA is ZT, TNA is TN, ULA is UB, and EU6, BP6, JY6, DA6, CA6, SF6, NE6 and MX6 are 6E, 6B, 6J, 6A, 6C, 6S, 6N and 6M.
- IQFeed's: a leading @ is dropped, and so is a Q before a metal or energy root (QGC is GC). EU is 6E and PX is 6M. The older CME codes TY, US, FV, TU, EC, BP, JY, AD, CD, SF, NE and MP read as ZN, ZB, ZF, ZT, 6E, 6B, 6J, 6A, 6C, 6S, 6N and 6M.
- Any other root keeps ES's hours: nothing moves, as in NinjaTrader for a market not in its table.
- The Message Log says once which market and hours the study found when they aren't ES's. It says so with the setting off too, and that the setting is off. With the setting on, it also says when it doesn't know the root. For example: *Use Instrument Hours: GCZ26_FUT_COMEX is GC, regular hours 07:20-12:30 CT. The session fields run at those hours.*
- Read that line once when you add the study to a market that isn't ES, above all on a feed not named here. If it says it doesn't know the root of a market in the table above, that market runs on ES's hours.
- The same root names `{root}` in a levels file or link.

**Updating from the study's 1.2.3 or older:** **Use Instrument Hours** is input 129 (input numbers are fixed). The Study Settings window lists it in 1. Global, after **Warn if Session Times Were Changed**. On charts that already had the study, check that it reads Yes. It needs a Sierra Chart with 160 study inputs; on an older one with 128 it has no input and stays on.

## AMT Toolkit: your daily levels

**Load them** from the chart's right-click menu:

- **Tatanka AMT: Edit Levels...** opens a large editor. Paste your levels and click **Save**.
- **Tatanka AMT: Paste Levels from Clipboard** loads copied levels in one click.

**Formats it reads:**

- The one-line paste line: date, pivot, then any prices. Prices above the pivot are resistance (RES1 nearest), below it support (SUPP1 nearest).

  ```
  2026-10-05, 7745.25, 7758.25, 7772.00, 7786.50, 7801.25, 7818.00, 7730.25, 7718.25, 7707.25, 7690.50, 7672.75
  ```

- The block with `Pivot Level:`, `Resistance Levels:` and `Support Levels:` lines (plus optional `Date:` and `Symbol:` lines).
- A whole Discord levels message. Titles, code fences and bold markers are skipped.

**If something's off,** the notice at the bottom of the chart says why: for example a thousands separator (`7,745.25`), or another symbol's levels. **STALE LEVELS** means the levels' date is older than the chart's trading date.

**Levels link (Patreon members).** Run `/connect` in the Tatanka Discord. The bot sends you a private link that ends in `/{root}.txt`. Paste it, exactly as is, into **2. Levels: Levels File or Link**. From then on every publish (8:15 AM and 4:45 PM CT) loads by itself: nothing to paste, no file to manage.

- `{root}` becomes the chart's symbol, so the same link works on ES, NQ, CL and GC charts, and micros read their parent (MES reads ES, MNQ reads NQ, MCL reads CL, MGC reads GC).
- Sierra Chart asks the link once per symbol however many charts show it: until the new levels are in, every 15 seconds for 10 minutes from a minute before each publish (8:14 and 4:44), then every minute for the rest of the hour; every 2 minutes for half an hour after new levels come in (in case of a correction); and every 30 minutes otherwise. It asks only while trades come in, so it asks nothing while the market is closed. A chart with no levels yet (a first setup, or a weekend) asks at once and shows the levels when the answer comes.
- If the link can't be reached, the chart keeps the last good levels, the notice says why, and the study asks again on its own. *Levels link unreachable* means no internet, or a firewall blocks Sierra Chart. If *Levels link answered an error* lasts, your membership may have lapsed or the link changed: run `/connect` again.
- The last good levels are cached in Sierra Chart's `Data\Tatanka\LevelsCache` folder, as for a file.
- Keep the link to yourself; it's personal. Sierra Chart saves study inputs in the chartbook in plain text, so don't share a chartbook that holds it.

**Levels file (optional).** Instead of pasting, set **2. Levels: Levels File or Link** to a text file with the same text. The study re-reads it every 5 seconds while live, so replacing the file each morning updates the chart. `{root}` becomes the chart's root symbol, and micros read their parent (MES reads ES). Use a full path, for example:

```
%USERPROFILE%\Documents\Tatanka\levels\{root}.txt
```

The last good levels are cached, so a reload without the file keeps them.

## AMT Toolkit: Discord alerts (optional)

1. In **your own** Discord server: **Server Settings → Integrations → Webhooks → New Webhook**, pick the channel and **Copy Webhook URL**.
2. In the study, set **19. Discord: Send Chart Alerts to Discord** to Yes and paste the URL into **19. Discord: Discord Webhook URL**.
3. Turn on push notifications for that channel on your phone.

Good to know:

- Only live alerts are sent. Loading history, recalculating and Replay send nothing.
- Only `https://discord.com/api/webhooks/...` URLs are accepted, and messages can't ping @everyone, users or roles.
- Sierra Chart's own alerts work whether or not Discord does.

> [!CAUTION]
> **Keep the webhook URL private.** Anyone who has it can post to your channel. Sierra Chart saves study settings in the chartbook as plain text, so don't share a chartbook or study settings file that contains it. If it leaks, delete the webhook in Discord and make a new one.

## Gap Analysis, TPO Profile and Session Volume Profile: each market's own hours

Gap Analysis, TPO Profile and the Session Volume Profile have NinjaTrader's **Use Instrument Hours** setting (v1.1.0 of each). It is on by default. The session times are written for ES's regular hours, 08:30-15:00 CT. On another market they move to that market's own regular hours: 07:20-12:30 CT on gold (GC, MGC), 08:00-13:30 CT on crude (CL, MCL) and 07:25-12:25 CT on silver (SI). A time nearer the open moves with the open. A time nearer the close moves with the close. A time before 07:00 or from 16:00 CT stays. ES, NQ, YM and RTY keep 08:30-15:00, so nothing changes there. The other markets are in the AMT Toolkit's table above, and micros use their parent's hours. Turn the setting off to run every time as typed, as before.

- **Gap Analysis:** **RTH start (Chicago)** and **RTH end (Chicago)** move, each on its own. They are Chicago time in any chart time zone, so leave them at their defaults. On GC a gap is the 07:20 open against the prior 12:30 close. Times that would meet or cross on a market (11:00 and 12:00 on CL) show a message on the chart instead. Use a bar size the market's open and close fall on: 1, 5 or 10 minutes on GC, 1 or 5 on SI.
- **TPO Profile:** **Session Start Time** and **Session End Time** move as a whole, in the **Timezone** input's zone. On America/Chicago (the default) leave them at 08:30-15:00: on GC the profile runs 07:20-12:30. In another zone, type ES's hours in that zone and the study moves them. On America/New_York type 09:30-16:00: on GC it runs 08:20-13:30 (07:20-12:30 CT). On UTC or Europe/London each bar moves at its own offset from Chicago time, so the session follows Chicago's daylight saving: on Europe/London 14:30-21:00 runs 13:20-18:30 on GC, and 13:20-21:00 in the weeks London's clocks and Chicago's don't line up. Chart Time Zone does what NinjaTrader does on that time zone. A short window either side of 11:45 whose ends would meet or cross moves as a whole (11:00-12:00 is 10:30-11:30 on CL). The chart label shows the session the profile uses. Use a bar size the market's open and close fall on: 1, 5 or 10 minutes on GC, 1 or 5 on SI.
- **Session Volume Profile:** **Session start** and **Session end** move as a whole, in the **Session time zone**. On ExchangeTemplate (the default) or Central leave them at 08:30-15:00: on GC the window runs 07:20-12:30. In another zone, type ES's hours in that zone and the study moves them. On Eastern type 09:30-16:00: on GC it runs 08:20-13:30. On Eastern, UTC and Chart each date's window moves at that date's offset from Chicago time, so it follows Chicago's daylight saving: on UTC 14:30-21:00 runs 13:20-18:30 on GC in Chicago's winter and 13:20-21:00 in its summer. A short window either side of 11:45 whose ends would meet or cross moves as a whole, as in TPO Profile. The chart label shows the window it uses. Sessions read from ticks work on any bar size. Sessions built from volume at price (the **Volume at price** option, and sessions that can't be read as single trades) take whole bars by their start time, so use a bar size the moved window falls on: 1, 5 or 10 minutes on GC, 1 or 5 on SI. On 15- or 30-minute GC bars such a session starts at 07:30.

**Which market.** Each study reads the market from the chart's symbol, as the AMT Toolkit does (Sierra Chart has no root field), so the AMT Toolkit and these studies run the same hours on a chart. These forms are read:

- Sierra Chart's own symbols and the usual feeds: GCZ26_FUT_COMEX, GCZ6.COMEX, GCZ26-COMEX, GC-202612-COMEX, GCZ26 and GC# are gold, and MGCZ2026 is micro gold. The month code and year are dropped.
- CQG's symbols (F.US.GCEZ26) use CQG's names: a trailing E is dropped (GCE is GC, CLE is CL, SIE is SI, MCLE is MCL), CPE is HG, NQM is QM, EP is ES, ENQ is NQ, TYA is ZN, USA is ZB, FVA is ZF, TUA is ZT, TNA is TN, ULA is UB, and EU6, BP6, JY6, DA6, CA6, SF6, NE6 and MX6 are 6E, 6B, 6J, 6A, 6C, 6S, 6N and 6M.
- IQFeed's: a leading @ is dropped, and so is a Q before a metal or energy root, so @GC# and QGC# are gold. EU is 6E and PX is 6M. A leading / is dropped too (/GCZ26).
- The older CME codes TY, US, FV, TU, EC, BP, JY, AD, CD, SF, NE and MP read as ZN, ZB, ZF, ZT, 6E, 6B, 6J, 6A, 6C, 6S, 6N and 6M.
- A market not in the table keeps ES's hours, as on NinjaTrader. While the setting is on, the Message Log says so once for each such symbol. On such a symbol, type the market's own hours and turn the setting off.

## Report a bug

Please [open an issue](../../issues/new/choose) with the **Bug report** form. The most useful reports include:

- your Sierra Chart version (**Help → About**), Windows display scale (for example 150%), whether OpenGL is on (**Global Settings → Graphics Settings**) and your **Intraday Data Storage Time Unit**;

## Differences from NinjaTrader

- **1hr 21 EMA** follows NinjaTrader 1.0.1, whose timing the TradingView script now shares. Exact steps once per source bar, at the first chart bar after that bar closes. Live is one EMA step from that EMA at the chart's price. On the bar that is forming, only source bars that have closed count, so Exact holds still while a source bar forms and a reload shows what the bar showed live. Where the chart's own bars make the source bars exactly, the study builds them from those, so no second chart is needed. A second or minute source uses the chart's bars when they divide it (1, 3, 5, 15 or 30 minute bars for 1 hour). On other charts (7, 45 or 90 minutes, bars as long as the source or longer, tick, volume and range bars, daily charts) it reads real source bars from a hidden intraday chart of the same symbol at the source timeframe, with this chart's Session Times, time zone and Days to Load. A day, week, month or year source uses the chart's bars on intraday charts with bars shorter than a day (tick, volume and range bars too) and on 1-day charts. On other charts (1440 minute bars or longer, daily charts of several days, weekly and monthly charts) it reads the hidden daily chart TPO Profile, If/Then and the AMT Toolkit use. Charts of the same symbol and settings share a hidden chart, and it stays in the chartbook. A hidden chart is read only while it holds the chart's own symbol and settings; otherwise Live and Exact show nothing and the Message Log says why. Smooth Scaled never opens one. While a hidden chart loads, Live and Exact show nothing. Minute and second source bars start at the trading day's start from **Chart Settings** session times, so 60 minutes lands on the hour on an ETH chart. Set the Session Times to the market's full session, as NinjaTrader's Trading Hours are. The trading day (the evening session, if you use one) must start at the market's open after its daily break: 17:00 Chicago (18:00 New York) for CME futures, GC included. A day session plus an evening session that starts there works the same. If the trading day starts elsewhere, for example an evening session from 13:30 after a day session that ends at 13:29:59, 60-minute source bars sit at :30 and day sources split at 13:30. Day, week, month and year sources follow the trading date, so the Sunday evening session counts as Monday. As in NinjaTrader, Live and Exact use source bars from the chart's first loaded day on, so they show nothing until the chart holds **EMA Length** source bars (21 hours by default, 21 days for a 1-day source). Raise **Days to Load** for long sources. The source can be Seconds, Minutes, Days, Weeks, Months or Years. NinjaTrader also offers tick, volume, range and other bar types; they are not offered here. Smooth Scaled rounds a half to the even number, as NinjaTrader does: a 2-hour chart gets EMA(10). A Quarterly chart counts as 3 x 30 days (NinjaTrader has no quarterly bars). With **Include Columns With No Data** on, the empty columns are skipped, as NinjaTrader has no such bars: they make no source bar and no EMA step, and the line holds the previous bar's value there. Bars with no volume that do not move are treated as empty too. So on a symbol whose data has no volume (a cash index, some forex feeds) such a bar takes no EMA step, where NinjaTrader counts it. Daily charts of several days, weekly and monthly charts place each bar at its last trading day's close, as NinjaTrader stamps it. Sierra Chart dates such a bar by its first day, so Live and Exact take the days from the hidden chart. Smooth Scaled takes the weekdays, so a holiday where its first source bar ends can move its first value by a bar. On tick, volume and range charts each bar is placed by its last trade (NinjaTrader's close stamp). If Sierra Chart has not loaded the bars' end times (for example on a chart opened before the study was added), the Message Log asks for **Chart >> Reload and Recalculate**. Until then a bar can step one bar early where a source bar closed between two bars. The value shows on the price scale, like NinjaTrader's price marker. A chart that already had version 1.0.0 of the study keeps its saved Subgraphs settings, so turn on the value label on the **Subgraphs** tab there, or remove the study and add it again. Sierra Chart has no Calculate setting. The forming bar updates on every trade, as with NinjaTrader's default (On price change), and a bar that has closed is recalculated once more. So where NinjaTrader's live bar kept a value its reload shows otherwise (the bar's last trade came before a source bar closed, and the next trade came after the bar ended), Sierra Chart shows the reload's. With NinjaTrader's On bar close, its closed bars show the same values as here.

Trades outside the chart's **Session Times** are left out, as NinjaTrader leaves out ticks outside its Trading Hours. The chart label is the study's Short Name, so a Short Name typed in Study Settings is replaced. The POC color is named **POC line** (NinjaTrader has two settings named POC). The histogram box has its own opacity input (0 = none, NinjaTrader's Transparent default); a translucent box is a Sierra Chart translucent range per period in Left and Right placement (bars show through it; it runs from the center of the bar before the period to the center of the bar nearest the period's end, so the developing period's box can end up to half a bar from its rows, and half a bar of a period's box shows when the bar before the period is the last one in view), and is blended with the chart background in ChartRightLatest (bars under it are hidden). Text is Segoe UI 8 pt (NinjaTrader's 11 DIPs). Editing colors or other display settings doesn't read the minutes again.

Trades (NinjaTrader 1.2.0 and later, which downloads them as the chart loads and at each close and then takes them live): read from this chart's own intraday data file (`sc.ReadIntradayFileRecordAtIndex`), so they need **Intraday Data Storage Time Unit** 1 Tick. The file is read before the engine is built, so the chart never shows values NinjaTrader would show only while its downloads run, and nothing is lost while one runs (NinjaTrader drops the live trades that come during its profile download: those minutes use 1-minute bars there). At the close the session's trades are already in the file, so the pd lines switch to their tick values at once (NinjaTrader shows its 1-minute value for the few seconds its download takes). A trade stamped exactly on the minute belongs to the minute it starts, as Sierra Chart builds its 1-minute bars (NinjaTrader: the minute it ends), so each minute's trades add up to the 1-minute bar beside it. A record of several trades (1-second storage) is not a trade: its minute uses its 1-minute bar and a session holding one uses 1-minute bars (NinjaTrader's downloads are always single trades). The present that picks the sessions and the period is the computer's clock in CT (the replay's time in a replay), as NinjaTrader's clock. **Value From Ticks (Sessions)** and **Profile From Ticks** are inputs 127 and 128 (input numbers are fixed), listed in their groups where NinjaTrader puts them: after **RTH Session for VA** and after **Calc Precision**; **Profile From Ticks** needs a Sierra Chart with 160 study inputs (the version of these headers, 2969), and on an older one with 128 it has no input and stays on, NinjaTrader's default. **Use Instrument Hours** (NinjaTrader 1.2.4) is input 129, listed after **Warn if Session Times Were Changed** as in NinjaTrader; with 128 inputs it has none either and stays on. NinjaTrader finds each market's hours by its instrument's root (its master instrument name); Sierra Chart has no root field, so the study reads the root from the chart's symbol (*each market's own hours* above: Sierra Chart's, CQG's and IQFeed's forms), and the Message Log says once which market and hours it found when they aren't ES's or, with the setting on, that it doesn't know the root. The same root now names `{root}` for a CQG symbol (before, `F.US.EPZ26` read as F). A line's alert watches only while the line is drawn (NinjaTrader 1.2.2): a hidden subgraph has no alert, and the OVN High and Low alerts stop at **Delete OVN Lines At** with their lines. Without a 1-minute chart the profiles use the chart's bars with NinjaTrader's warning. "loading chart and secondary history" shows while a chart downloads or the 1-minute chart has not caught up. In a Single Chart replay the hidden chart isn't replayed, so the forming bar's profile stops at the replay time with that minute complete; replay All Charts in Chartbook (or use a 1-minute chart) for exact replays. A trading day starts at 17:00 CT, as in NinjaTrader, whatever the chart's Session Times. A bar cut short by an early close (12:15 on a 30-minute chart) keeps its true start, so no minute counts twice (NinjaTrader starts it 30 minutes before its close, inside the previous bar). The completed profiles are translucent ranges (the bars show through) with each row's width rounded to whole bars, as TradingView draws them; the developing profile, in the chart's right fill space, keeps NinjaTrader's exact widths, blended with the chart background, so with a negative **Profile Offset** or left alignment it hides the bars under it. With **Include Columns With No Data** the empty columns are not bars to the study (NinjaTrader has none): the RTH VWAP and the 80% Rule fill run across them, and the completed profiles stay in view for 4,500 bars with trades, as in NinjaTrader. Lines that start at a bar's start begin at the previous bar's center, as NinjaTrader's do; each past day's IB and pd lines take the current subgraph settings, and showing or hiding a pd line gives the past days NinjaTrader would show after a reload (each line as it stood before it switched at the close, and NinjaTrader's 20-day cut as the lines shown would have made it) without recalculating. Every line is labeled with its subgraph's name; the trapped settlement line is named with the **TRAP ACTIVE** subgraph's Name (NinjaTrader's Trap Text). The late spike's two sides follow their own subgraphs: hiding **Spike Base (Supp)** stops bullish spikes, hiding **Spike Base (Res)** bearish ones (both hidden is NinjaTrader's Show Late Spike off). **Globex Start Time** is a Time input, so the overnight count can start at any minute (NinjaTrader takes whole hours). An IB label on the right stays at the line's end once the line stops at the Stop Time (NinjaTrader keeps it at the current bar, so overnight it drifts away from its line; TradingView stops it with the line); with **Extend IB Levels** Right or Both the line runs to the chart's right edge and its label stays at the current bar, as in NinjaTrader. The 80% Rule fill is a translucent range (the bars show through) over each run of bars from one bar's center to the next bar's center (NinjaTrader shades each bar from half a bar before its center to half a bar after: the same width, half a bar to the right), its transparency an input (**80% Rule Fill Transparency**, 93), the active and confirmed colors the **80% Rule Fill** subgraph's primary and secondary colors. The single prints are translucent ranges too (the bars show through), each block from the bar before the one that first traded it (NinjaTrader's start) to 30 minutes past the current bar (to the nearest bar), but not past the end of the chart's Session Times: NinjaTrader's time axis has no bars in the break after the session, so after the close and over the weekend its single prints end at the session's last bar (an early close the Session Times don't hold keeps the 30 minutes); their transparency an input (**Single Print Transparency**, 90: NinjaTrader's 10% orange), their color the **Single Print** subgraph's; hidden (fill and borders), they are still tracked and count toward the 2,000 structures. Their borders (NinjaTrader's Border Width 0 is the **Single Print Border** subgraph Hidden, the default) outline each block as NinjaTrader does; a part of a block before the first loaded bar is blended over the chart background. **Poor High** and **Poor Low** each have a subgraph (both hidden is NinjaTrader's Show Poor Highs/Lows off), and so does each naked POC kind (a hidden kind is not tracked, as NinjaTrader's Show switch). The RTH open (dOpen) and the weekly open each have a label size input with Off (NinjaTrader's one Opens Show Labels switch serves both). Each past day's dOpen line is kept like its IB and pd lines, so showing **dOpen** shows the past days at once. The prior week's and month's high and low, as in NinjaTrader, need the whole prior week and month loaded, and a week whose first bar is not Sunday 17:00 (a Monday holiday) has no weekly open. An IB line extended both ways (**Extend IB Levels** Both) keeps the IB's label switch, and Force on Top's **Daily Levels (All)** lifts only the daily levels: NinjaTrader puts every line extended both ways in the daily levels' label group, so its IB labels then follow the levels' Show Labels and rise with them. The forming bar's profiles and alerts use the 1-minute bar as it stands at each chart update (NinjaTrader updates its primary series before its 1-minute series on each tick, so its preview reads the minutes one tick late). Prices are snapped to the tick and shown in the chart's price format. Daily levels: Sierra Chart's text inputs are single-line, so the paste box is edited in a multi-line editor from the chart's right-click menu (**Tatanka AMT: Edit Levels...**) or filled from the clipboard (**Tatanka AMT: Paste Levels from Clipboard**); the text is read exactly as NinjaTrader reads it, with the same messages and .NET's number rules. The levels file is re-read at most every 5 seconds while the chart is live, and its last-good cache is kept in Sierra Chart's `Data\Tatanka\LevelsCache` folder (NinjaTrader keeps its own under its user folder, so the two platforms don't share caches). Levels link (NinjaTrader 1.1.0): Sierra Chart makes the request (`sc.MakeHTTPRequest`) and gives the study the file or an error (its documented "ERROR" for an error status), never the HTTP status or headers. So a link that is not active (403) and a symbol with nothing published (404) read as one error, *Levels link answered an error; retrying. If it lasts, run /connect...*, retried like a server error (after 1 to 15 minutes; NinjaTrader asks every 30 minutes then). Sierra Chart sends its own headers: no NinjaTrader User-Agent, and no If-None-Match, so an unchanged file comes again in full and changes nothing. A request with no answer in 15 seconds counts as timed out (NinjaTrader gives up after 10). A chart with no levels at load doesn't wait for the link's first answer (NinjaTrader waits up to 3 seconds); the levels show when it comes, the engine built again with them. Sierra Chart runs one request of a study at a time, so the link waits while a Discord message is in flight, and Discord goes first. One download per link serves every chart in this Sierra Chart (NinjaTrader: every chart in NinjaTrader). The link asks only when a trade came since its last read (NinjaTrader asks on its ticks). The usual link is taken as NinjaTrader takes it; a link with `%` escapes, spaces or other characters .NET would rewrite, a path part ending in a dot, or an unusual host (not plain letters, digits, hyphens and dots) is refused with NinjaTrader's message. Each level takes its kind's subgraph (**PIVOT**, **RES** or **SUPP**: color, width, style, label text color, and the label text plus the level's number, so a renamed RES subgraph renames RES1, RES2...); Hidden hides that kind's lines and keeps their labels and zones (NinjaTrader's one Show Level Lines switch hides all three kinds). A flipped level takes the other side's color and "FLIPPED " before its name, as in NinjaTrader. The zone borders have the **Level Zone Border** subgraph (Hidden = no borders; the width is editable, NinjaTrader's is 1; the color is each level's). The zones are translucent ranges from the chart's first bar to its right edge. A **Dotted** line (the levels' default, also IB Midpoint and the poor highs/lows) is drawn as dots: NinjaTrader's Dotted style draws nothing on its charts (Direct2D's dots have no length with the flat line ends NinjaTrader uses), so there a dotted level shows only its label and zone; choose Hidden on the subgraph for that look. Discord: Sierra Chart makes the request (`sc.MakeHTTPPOSTRequest`, its own connection and certificate checks) and gives the study only Discord's answer, not the HTTP status, so the answer decides: the posted message (delivered), a rate limit (later messages wait `retry_after`, 1 to 60 seconds, and the message is sent once more), Discord's error code ("Discord error 10015" where NinjaTrader says "HTTP 404"), Sierra Chart's own "ERROR" (an HTTP or connection error it doesn't tell apart; later messages wait 2 seconds in case it was a rate limit), or no answer within 15 seconds (a connection error; NinjaTrader gives up after 5). Sierra Chart runs one request at a time, so after those 15 seconds the next message still waits for Sierra Chart's answer, at most a minute. A failed message is never resent, as in NinjaTrader. The study posts to the webhook's Discord API version 10 address (`https://discord.com/api/v10/webhooks/...`, the same webhook) whatever form of the URL was pasted: Discord answers the usual unversioned URL with its old default version, whose rate-limit answer counts `retry_after` in milliseconds (NinjaTrader reads the HTTP header, which is in seconds). The message is `[symbol] alert | close price | time CT` with Sierra Chart's symbol (NinjaTrader's full instrument name) and the time of the latest trade (NinjaTrader stamps the forming bar's end, so a 09:31 alert on a 5-minute chart said 09:35:00); a message cut at 1,900 characters never splits an emoji in two. Alerts: Sierra Chart's alert sound list (**Alert Sound**: No Alert = none, No Sound = the Alerts Log only; Discord follows its own switch); the levels are checked once per chart update with the latest price (NinjaTrader checks every tick), so a cross that reverses within one update interval is missed; a full recalculation or a reload never repeats an alert already given on the forming bar (NinjaTrader's reload can). Editing colors, transparencies, label settings, the dashboard or the profile's width, alignment and offset applies at once without recalculating. **Hide Study** draws nothing but keeps the alerts running.
