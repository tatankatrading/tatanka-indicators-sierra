# Tatanka Indicators for Sierra Chart (beta)

Sierra Chart versions of the nine free, open-source Auction Market Theory indicators from [Tatanka Trading](https://tatankatrading.com), built as ACSIL custom studies. The originals for NinjaTrader 8 and TradingView live in [tatanka-indicators](https://github.com/tatankatrading/tatanka-indicators).

> [!WARNING]
> **Beta: these studies haven't been verified in Sierra Chart yet.** They were ported line by line from the NinjaTrader versions and checked against NinjaTrader's own calculations, but nobody at Tatanka Trading has run them in a live Sierra Chart setup. Expect rough edges, especially in how Sierra Chart draws see-through shading, loads its hidden 1-minute and daily charts, and scales text on high-DPI displays. The NinjaTrader and TradingView versions remain the reference. If something looks wrong, slow or different from those, please [report it](#report-a-bug).
>
> These indicators are for education and chart analysis only. They don't give buy or sell signals, they aren't financial advice, and they come with no warranty (see the [license](LICENSE)). Futures trading carries substantial risk of loss.

## Install

Each indicator is one `.cpp` file that builds into its own DLL.

1. Copy the `.cpp` file into the `ACS_Source` folder inside your Sierra Chart folder (usually `C:\SierraChart\ACS_Source`).
2. In Sierra Chart: **Analysis → Build Custom Studies DLL**, then **File → Select Files** and pick the file.
3. **Build → Remote Build - Standard.** Sierra Chart compiles it on its server, so you don't need Visual Studio.
4. On a chart: **Analysis → Studies → Add Custom Study**, open the Tatanka DLL and add the study.

**AMT Toolkit:** use a 1 to 30 minute chart whose **Session Times** (Chart Settings) cover the full Globex session (17:00-16:00 CT for CME; the study says so otherwise). Load at least the whole prior month (**Days to Load** about 60) for the prior month's value, high and low and the monthly naked POCs, and the hidden daily chart needs 30 trading days for the daily ATR. The study opens a hidden 1-minute chart and a hidden daily chart of the same symbol (shared with the Periodic and Auto Anchored Volume Profiles and with TPO Profile and If/Then); they stay in the chartbook. Enable alerts on one chart per instrument, or every alert fires twice.

**Hidden charts are expected.** The AMT Toolkit and the Periodic and Auto Anchored Volume Profiles open a hidden 1-minute chart of the same symbol, and the AMT Toolkit, TPO Profile and If/Then open a hidden daily chart. They show up in the **Window** menu. Leave them open: the studies read their data from them, and charts of the same symbol share them.

### AMT Toolkit: daily levels

**Paste box.** **2. Levels: Paste Levels Here** takes NinjaTrader's one-line paste line: the date, the pivot, then any prices (above the pivot = resistance, RES1 nearest; below = support, SUPP1 nearest):

```
2026-10-05, 7745.25, 7758.25, 7772.00, 7786.50, 7801.25, 7818.00, 7730.25, 7718.25, 7707.25, 7690.50, 7672.75
```

or the three-line block (`Pivot Level:` / `Resistance Levels:` / `Support Levels:`, with optional `Date:` and `Symbol:` lines). If both are pasted, the paste line wins. A whole Discord message works too: titles, code fences, bold markers and comments are skipped. Sierra Chart's text inputs are single-line, so edit the levels from the chart's right-click menu:

- **Tatanka AMT: Edit Levels...** opens a multi-line editor with the box's text and NinjaTrader's instructions; **Save** writes it back and the chart redraws with the new levels.
- **Tatanka AMT: Paste Levels from Clipboard** loads copied levels in one click. If the clipboard holds no levels, the Message Log says why and the box is left as it was.

A rejected paste draws no levels and the notice at the bottom of the chart says why (for example a thousands separator, `7,745.25`, or another symbol's levels: a `Symbol:` line that isn't this chart's, or a pivot more than 20% from the chart's price). **STALE LEVELS** shows when the levels' date is older than the chart's trading date (a later date is fine: the Globex levels published after the close carry the next date).

**Levels file (optional).** Point **2. Levels: Levels File** at a text file holding the same text instead of pasting. The study re-reads it every 5 seconds while the chart is live, so a file that's replaced each morning updates the chart without reloading. `{root}` in the path becomes the chart's root symbol, and micros read their parent (MES reads ES, MNQ reads NQ, MCL reads CL, MGC reads GC); `%VARIABLES%` are expanded. Use a full path, for example:

```
%USERPROFILE%\Documents\Tatanka\levels\{root}.txt
```

A file without a `Date:` line takes the trading date of its last change. A rejected or missing file keeps the last valid levels on the chart (the notice says why), and the last good levels are cached in Sierra Chart's `Data\Tatanka\LevelsCache` folder, so a reload without the file still has them. The paste box is the fallback until a file or the cache has loaded. Leave **Levels File** blank to use the paste box.

### AMT Toolkit: Discord alerts (optional)

1. In your own Discord server: **Server Settings → Integrations → Webhooks → New Webhook**, pick the channel, **Copy Webhook URL**.
2. In the study: **19. Discord: Send Chart Alerts to Discord** = Yes, and paste the URL into **19. Discord: Discord Webhook URL**.
3. Turn on Discord push notifications for that channel on your phone.

Only live alerts are sent: historical loading, a recalculation and Replay send nothing. Discord doesn't depend on **Alert Sound** (with No Alert, Sierra Chart gives no alert of its own but Discord still sends), and Sierra Chart's alerts fire whatever happens to Discord. Only an `https://discord.com/api/webhooks/...` URL is accepted (otherwise the chart says "Discord disabled"), a message can't ping @everyone, users or roles, and at most one message goes out every 500 ms per webhook (charts sharing a webhook share the pacing), with at most 32 waiting. Discord problems show in the chart's notice, never with the URL.

**Keep the webhook URL private.** Anyone with it can post to your channel. Sierra Chart saves study inputs in the chartbook in plain text, so don't share a chartbook (or a study settings file) that holds it. If the URL leaks, delete the webhook in Discord and create a new one.

## Report a bug

Please [open an issue](../../issues/new/choose) using the **Bug report** form. The most useful reports include:

- your Sierra Chart version (**Help → About**), Windows display scale (for example 150%), whether OpenGL is on (**Global Settings → Graphics Settings**) and your **Intraday Data Storage Time Unit** (**Global Settings → Data/Trade Service Settings**);
- which study, the symbol and bar period, and any settings you changed;
- screenshots (zoomed-in crops are best), and anything red in **Window → Message Log**;
- for a build failure, all the text in the **Output** area of the Build Custom Studies DLL window.

**Never post a Discord webhook URL** in an issue or a screenshot. Anyone who has it can post to your channel.

## Differences from NinjaTrader

- **1hr 21 EMA** builds the higher-timeframe bars from the chart's own bars, so no second chart is needed. Minute and second buckets start at the trading day's start from **Chart Settings** session times, so 60 minutes lands on the hour on an ETH chart. Exact HTF steps on the bar that closes each HTF bar, as on TradingView (NinjaTrader's version steps one bar later), and Live HTF uses only closed HTF bars plus the current close.
- **Level Lines** sets line colors, styles and widths on the **Subgraphs** tab. Type levels in the **Levels** input, or right-click the chart and choose **Tatanka Level Lines: Edit Levels...** for NinjaTrader's large editor. The range shading is a transparent Rectangle Highlight drawing. Label backgrounds are blended with the chart background, since Sierra Chart's drawing callback has no transparency.
- **If/Then:** Sierra Chart's text inputs are single-line, so the rows are loaded from the chart's right-click menu: **Tatanka If/Then: Edit Rows...** opens a multi-line editor like NinjaTrader's, and **Paste Rows from Clipboard** loads a copied block in one click. The background color's opacity is its own input (**Table Background Opacity %**). The ATR zones are transparent Rectangle Highlight drawings; other translucent colors are blended over the background. *Zone fill opacity* is named **Zone Fill Transparency** here, since that's what it measures (100 = invisible). Position coloring and ATR zones need the daily ATR, so turning either on opens a hidden daily chart of the same symbol (it stays in the chartbook, like NinjaTrader's separate daily series).
- **Gap Analysis:** **RTH start (Chicago)** and **RTH end (Chicago)** are Sierra Chart time inputs instead of HHmmss numbers (still Chicago time with daylight saving, whatever the chart's time zone). Font sizes are in points: 9 and 10 by default, NinjaTrader's 12 and 13. Alerts use Sierra Chart's alert sound list (**Alert sound**, Alert Sound 1 by default; No Sound gives a visual Alerts Log entry only), or a WAV named in **Alert sound file** (a file in Sierra Chart's `AlertSounds` folder, or a full path). The zone shading is transparent Rectangle Highlight drawings from the opening bar's center to the center of the bar after the zone's last bar (or to the right edge while extended), so a gap filled on its opening bar is still one bar wide (NinjaTrader's zone starts half a bar earlier). The shading is drawn underneath the price bars, so the zone outlines, target lines, labels and the table always stay on top of it, as in NinjaTrader (a Sierra Chart drawing above the bars would also cover the study's labels and table); the cost is that the bars inside a zone are not tinted by it. The outlines, target lines, labels and the table are blended over the chart background, since the drawing callback has no transparency. With **Include Columns With No Data** on, the empty columns are skipped: they never open a session, set the RTH close or fill a gap, and the bar counts (**BARS** and the fill alert) leave them out, as NinjaTrader has no such bars. With **Maximum visible gaps** above 0 the study updates continuously so the shading follows scrolling (at the chart update interval). A gap exactly at the minimum size always counts (NinjaTrader's exact comparison can miss it by rounding). **Hide Study** keeps tracking gaps and sending alerts, like turning off NinjaTrader's Visible.
- **TPO Profile:** **Session Start Time** and **Session End Time** are Sierra Chart time inputs instead of the HHmm-HHmm text, in the **Timezone** input's zone (America/Chicago by default, daylight saving included, whatever the chart's time zone; choose Chart Time Zone for NinjaTrader's behavior). Equal start and end times mean a 24-hour session from the start time (NinjaTrader draws nothing then). **Auto Row Height** reads the daily ATR(10) from a hidden daily chart of the same symbol (shared with If/Then), so it works on charts that load only a few days (NinjaTrader uses 8-tick rows until its chart has loaded 11 days); on an RTH-only chart that ATR is the full trading day's, so rows come out a little taller than with NinjaTrader's RTH daily bars. Charts of the same symbol share that daily chart; a chart switched to another symbol finds or opens a daily chart of its new symbol instead of changing the shared one (so one hidden daily chart stays in the chartbook per symbol used), and a daily chart that no longer holds the chart's symbol is looked up again, so the row height always comes from the chart's own symbol, as on NinjaTrader. Each session keeps the row height it started with (NinjaTrader re-prices an older profile when the ATR changes). **Box Transparency** keeps NinjaTrader's default of 0 (opaque boxes; TradingView's look is 75). Translucent boxes and the outline fills are drawn by Sierra Chart as translucent ranges under the study's letters, POC and value-area lines and outline strokes, so the bars show through and the letters stay readable (**Box Drawing** = Transparent); **Solid** blends them with the chart background instead, which is faster but hides the bars under a profile unless **Draw Study Underneath Main Price Graph** is on. Where an older day's outline skips untraded prices (its edge runs diagonally there), the study fills that gap itself, exactly to the diagonal, blended with the chart background, since none of that day's bars trade there. Grid lines and the lines of studies drawn under this one don't show through that part of the fill, though they do through the rest of the outline (NinjaTrader's fill is translucent there too; as translucent ranges, the gap's fill would follow the diagonal in steps of one bar on every gap). When **X Offset** moves an outline over other sessions' bars, those gaps are translucent ranges too, so the bars show through them as well, and their fill then follows the diagonal in steps of one bar (the edge line stays exact). Translucent boxes and outline parts before the chart's first bar, or starting past its last bar (in the right-side fill space, with a positive **X Offset**), are blended with the chart background as well, since a Sierra Chart range starts on a loaded bar, so grid lines don't show through them there either. All outline fills are drawn before any outline's edges and lines, so an older day's extended POC line stays visible across a newer outline (NinjaTrader shows it through the translucent fill). Letters are Arial 8 pt (NinjaTrader's 10 DIPs) and are drawn after all the boxes of a profile, so a neighboring box never cuts a letter off. Columns are one chart bar each, also across session breaks, and **X Offset (Bars)** shifts by bars. The developing profile includes the bar that is forming (NinjaTrader shows closed bars only). A session is saved on its last bar, so on an RTH-only chart the day's profile appears right after the close instead of the next morning. A day that traded in a single row gets an outline too. Daily, weekly and monthly charts show a message instead of a profile. On tick, volume and range charts each bar is placed by its last trade (NinjaTrader's close stamp); if Sierra Chart has not loaded the bars' end times (for example on a chart opened before the study was added), the study asks for **Chart >> Reload and Recalculate** instead of placing bars by their start times. With **Include Columns With No Data** on, the empty columns are skipped, as NinjaTrader has no such bars.
- **Session Volume Profile:** built from the chart's own tick-by-tick data, so set **Intraday Data Storage Time Unit** to **1 Tick** (Global Settings >> Data/Trade Service Settings) and download tick history. Trades outside the chart's **Session Times** are left out, as NinjaTrader leaves out ticks outside its Trading Hours. The study reads the tick file in short slices so the chart stays responsive, the newest session first ("reading tick data..." shows until it's in, and again while data that a historical download or backfill added to the open chart is read), then the older ones. Sessions that can't be read as single trades (older history stored as 1-second records, sessions before the chart's tick file on a continuous contract, back-adjusted prices, or tick data that doesn't add up to the chart's volume, as an older contract's sessions on a continuous contract chart) are built from Sierra Chart's volume at price instead, with up/down volume from bid/ask; the chart label says how many ("not from ticks") and the message log says why. **Volume data** can also choose bid/ask or volume at price for every session (the fastest: no tick file reading; "waiting for volume at price..." shows until Sierra Chart has built it). The study keeps Sierra Chart's volume at price on for the chart, which costs some memory; with a **Volume at Price Multiplier** above 1, the rows of the sessions built from it are that many ticks apart. Sessions built from volume at price (the **Volume at price** option, and sessions that can't be read as single trades) take whole bars by their start time, so they match the session window exactly only on bars that divide it (1, 5, 15 or 30 minutes for 08:30-15:00). Longer bars add or drop trades at the window's edges: on 60-minute bars the 08:00 bar is left out, so the session misses 08:30-09:00. On 1-day bars only a window that holds the bar's start gets such a profile, so an ETH chart (daily bars start at 17:00) gets none for 08:30-15:00; when every session comes from volume at price, the study says so instead of "no ticks". Intraday bars up to 1 day work when the sessions are read from the tick data (NinjaTrader's 1440-minute bars); bars of several days show a message instead, since one bar would span several sessions. **Session start** and **Session end** are Sierra Chart time inputs instead of HH:mm text; **ExchangeTemplate** means America/Chicago (Sierra Chart has no trading-hours time zone; right for CME, CBOT, NYMEX and COMEX), and **Chart** is this chart's own time zone. POC, VAH and VAL are exact on every bar, live and after a reload (NinjaTrader refreshes them at most every 200 ms live); they show as price-scale markers and in the Chart Values window. The chart label is the study's Short Name, so a Short Name typed in Study Settings is replaced. The POC color is named **POC line** (NinjaTrader has two settings named POC). The histogram box has its own opacity input (0 = none, NinjaTrader's Transparent default); a translucent box is a Sierra Chart translucent range per session in SessionRight (bars show through it, the profile and lines stay on top), and is blended with the chart background in ChartRightLatest (bars under it are hidden). A half-tick POC (an even number of ticks per row) is drawn at its true price, and its text uses the chart's price format instead of NinjaTrader's rounding to a tick: on ES and NQ (two decimals) 7879.625 shows as 7879.62 or 7879.63, and on CL and GC, whose price formats have a tick's decimals, it shows a whole tick, as NinjaTrader does. Text is Segoe UI 8 pt (NinjaTrader's 11 DIPs). Editing colors or other display settings doesn't read the tick data again. Changing the value area recomputes the shown profiles and their levels at once; sessions older than **Sessions to retain** (kept only as their per-bar POC, VAH and VAL) are read again in the background for those values, and a larger **Sessions to retain** reads only the sessions it brings back.
- **Periodic Volume Profile:** built from 1-minute bars, as in NinjaTrader: on a 1-minute chart (or second bars that divide a minute, such as 15 or 30 seconds) from the chart's own bars, otherwise from a hidden 1-minute chart of the same symbol that the study opens with the chart's Session Times, time zone, continuous-contract setting and Days to Load. Charts and studies of the same symbol and settings share that hidden chart; it costs about as much memory as a 1-minute chart of those days, and it stays in the chartbook when the study is removed or those settings change (other charts may be reading it). A 1-minute chart is the quickest setup (no second chart to load); on it the study keeps its own table of the minutes, about 100 bytes per minute of history (some 65 MB for Yearly x 5). Periods follow the trading date from **Session Times** (NinjaTrader's Trading Hours template): for CME ETH the trading day must start at 17:00 CT so a Sunday evening belongs to Monday. Raise **Days to Load** (Chart Settings) for longer periods; only the minutes inside the chart's own loaded range are used, so a shared hidden chart with more days changes nothing. "waiting for 1-minute history" shows while the minute history loads or downloads (no profile is drawn meanwhile, so a half-loaded one never passes for a complete one), and a message says so if Sierra Chart can't open the 1-minute chart. In a Single Chart replay the hidden chart isn't replayed, so the profile stops at the replay time with that minute complete; replay All Charts in Chartbook (or use a 1-minute chart) for exact replays. **Volume data** can instead use Sierra Chart's volume at price: the volume where it traded, up/down from bid/ask, whole bars by their start time (the chart reloads once when you choose it, and "waiting for volume at price..." shows until it's built). POC, VAH and VAL show on the last bar only (price-scale markers, Chart Values window and chart label), as NinjaTrader keeps them only for the live bar; earlier bars keep what they showed while they were the last, until a reload or full recalculation. The developing profile updates on every chart update (NinjaTrader refreshes it at most every 250 ms). Lines extended **UntilTouched** stop at the center of the first later bar of the chart whose range reaches them, compared in ticks (NinjaTrader's double comparison can miss an exact touch on CL or GC). On bars shorter than a minute (second, tick, volume or range bars) a line can stop at a bar inside the next period's first minute, as NinjaTrader shows in real time; a reloaded NinjaTrader chart (without Tick Replay) skips those bars and runs the line on. The chart label is the study's Short Name, so a Short Name typed in Study Settings is replaced. The POC color is named **POC line** (NinjaTrader has two settings named POC). The histogram box has its own opacity input (0 = none, NinjaTrader's Transparent default); a translucent box is a Sierra Chart translucent range per period in Left and Right placement (bars show through it; it runs from the center of the bar before the period to the center of the bar nearest the period's end, so the developing period's box can end up to half a bar from its rows, and half a bar of a period's box shows when the bar before the period is the last one in view), and is blended with the chart background in ChartRightLatest (bars under it are hidden). Text is Segoe UI 8 pt (NinjaTrader's 11 DIPs). Editing colors or other display settings doesn't read the minutes again.
- **Auto Anchored Volume Profile:** built from 1-minute bars with the Periodic Volume Profile's engine and data sources: on a 1-minute chart (or second bars that divide a minute) from the chart's own bars, otherwise from a hidden 1-minute chart of the same symbol with the chart's Session Times, time zone and continuous-contract setting. On an intraday chart the hidden chart loads the chart's own **Days to Load**, so raise it to reach back before the anchor's start (about 400 days for Year), as in NinjaTrader. A **1 Day** chart is a Historical Daily chart of one day per bar (an intraday chart of 1-day bars gets the same layout; other intraday bar lengths the intraday one); weekly, monthly and multi-day charts show NinjaTrader's message. On a Historical Daily chart the hidden chart loads only the days the anchor needs (30 for Session and Week, 60 for Month, 120 for Quarter, 400 for Year, whole years back to the block's start for Decade and Century, never before the daily chart's first bar), not the daily chart's years of history, and the profile takes the minutes of the trading dates from 14 days before the anchor (so the incomplete-history notice means what it says) through the last daily bar's date, so a Sunday evening session joins once Monday's daily bar appears. The anchor follows the trading date from **Session Times**: for CME ETH the trading day must start at 17:00 CT so a Sunday evening belongs to Monday, on a daily chart too (its hidden chart takes the daily chart's Session Times). "waiting for 1-minute history" shows while the minute history loads or downloads; on a Historical Daily chart the study does not wait for the minutes to reach the daily chart's last date (daily and intraday data are separate files, and some feeds have no recent minutes). **Volume data** can use Sierra Chart's volume at price on intraday charts (whole bars by their start time; the chart reloads once when you choose it); a Historical Daily chart has none, and a message says so. POC, VAH and VAL show on the last bar only (price-scale markers, Chart Values window and chart label), as NinjaTrader keeps them only for the live bar. The profile updates on every chart update (NinjaTrader refreshes it at most every 250 ms). The chart label is the study's Short Name, so a Short Name typed in Study Settings is replaced. The POC color is named **POC line** (NinjaTrader has two settings named POC). The histogram box has its own opacity input (0 = none, NinjaTrader's Transparent default); a translucent box is a Sierra Chart translucent range from the center of the bar nearest the anchor to the bar nearest the latest minute (on a 1 Day chart from the first daily bar's center to the last's, half a bar short of NinjaTrader's box at each end), and, when the profile is pinned, across the whole chart from its first bar to its right end (NinjaTrader's pinned box spans the visible chart less the padding, and none shows when you scroll back before the anchor); a profile within one daily slot blends its box with the chart background instead. Text is Segoe UI 8 pt (NinjaTrader's 11 DIPs).
- **AMT Toolkit:** everything NinjaTrader's toolkit draws, tracks and alerts is ported. The value: the volume profile (Session, Weekly, Monthly or Yearly) with its Developing POC/VAH/VAL lines, the completed profiles and the walls; the prior day's value (pdPOC, pdVAH, pdVAL); the prior month's value (pmPOC, pmVAH, pmVAL); the RTH VWAP; the daily ATR; the dashboard frame; the price-axis tags; Force on Top; Hide All Labels & Price Tags; the session-time warning; and the alerts of those lines. The auction read: the overnight high/low; the prior day's high/low/open (the custom session's, switching at 15:00, or the whole trading day's) with each past day's lines; the initial balance; the settlement and the overnight inventory with trap detection; the open location and the gap test; the Dalton day type; the 80% Rule and its fill; the late spike's base; the dashboard's DAY TYPE, OVN INVENTORY, OPEN and 80% RULE rows; the pdHigh, pdLow, IB High and IB Low tags; and their alerts (OVN, IB, prior day high/low crosses, the trap, the spike base touch, the confirmed 80% Rule). The unfinished business: the daily, weekly and monthly naked POCs (from 1-minute bars, extended right until traded through, with their touch alerts); the TPO single prints and poor highs/lows; the prior week's and month's high and low; the weekly open and the RTH open line (dOpen, with each past day's); the pwHigh, pwLow, pmHigh and pmLow tags; and their alerts. The daily levels: the pivot, resistances and supports from the paste box or a levels file, with their zones, color flips, labels, the dashboard's PIVOT row and their alerts; and the Discord webhook for every alert. Settings: Sierra Chart has 128 inputs for NinjaTrader's 276 settings, so the inputs carry the group number in their names ("11. Profile: Value Area %"), and every line's color, width, style, label text color and Show switch are on the **Subgraphs** tab, one subgraph per line named with NinjaTrader's line name: **Draw Style** Hidden is NinjaTrader's Show switch off, **Use Labels Color** off is NinjaTrader's Transparent label color (the line's own color), and the subgraph's **Name** is the label text (NinjaTrader's Trap Text, generalized). Where NinjaTrader shares one color or switch between lines (pmVAH and pmVAL, the three pd value lines), each line has its own subgraph with the same default. A group's **Show Labels** switch is the **Off** choice of its **Label Size** input; **Manual Tick Size** and the nPOC **Manual Bin Size** are 0 for Auto; the VWAP and inventory hour/minute pairs are Sierra Chart Time inputs; the session windows stay NinjaTrader's HHmm-HHmm[:days] text, always Central time whatever the chart's time zone; NinjaTrader's Limits are fixed at 100,000 rows and 2,000 structures. Colors with alpha have their own inputs: **pdVAH/pdVAL Opacity (%)** (50, NinjaTrader's half-transparent purple), **VA/Outer Transparency**, **Wall Transparency**. Data: 1-minute bars come from the chart itself on a 1-minute chart, otherwise from the hidden 1-minute chart the Periodic and Auto Anchored Volume Profiles open (shared with them, with the chart's Days to Load); the prior month's 30-minute bars are built from those minutes (no third chart); the daily ATR comes from the hidden daily chart TPO Profile and If/Then use, over its whole history (TradingView's result; NinjaTrader's ATR starts from the chart's first loaded day). Without a 1-minute chart the profiles use the chart's bars with NinjaTrader's warning. "loading chart and secondary history" shows while a chart downloads or the 1-minute chart has not caught up. In a Single Chart replay the hidden chart isn't replayed, so the forming bar's profile stops at the replay time with that minute complete; replay All Charts in Chartbook (or use a 1-minute chart) for exact replays. A trading day starts at 17:00 CT, as in NinjaTrader, whatever the chart's Session Times. A bar cut short by an early close (12:15 on a 30-minute chart) keeps its true start, so no minute counts twice (NinjaTrader starts it 30 minutes before its close, inside the previous bar). The completed profiles are translucent ranges (the bars show through) with each row's width rounded to whole bars, as TradingView draws them; the developing profile, in the chart's right fill space, keeps NinjaTrader's exact widths, blended with the chart background, so with a negative **Profile Offset** or left alignment it hides the bars under it. With **Include Columns With No Data** the empty columns are not bars to the study (NinjaTrader has none): the RTH VWAP and the 80% Rule fill run across them, and the completed profiles stay in view for 4,500 bars with trades, as in NinjaTrader. Lines that start at a bar's start begin at the previous bar's center, as NinjaTrader's do; each past day's IB and pd lines take the current subgraph settings, and showing or hiding pdHigh, pdLow or pdOpen gives the past days NinjaTrader would show after a reload (it keeps the lines as they stood at the first change of a shown line, usually the 15:00 switch) without recalculating. Every line is labeled with its subgraph's name; the trapped settlement line is named with the **TRAP ACTIVE** subgraph's Name (NinjaTrader's Trap Text). The late spike's two sides follow their own subgraphs: hiding **Spike Base (Supp)** stops bullish spikes, hiding **Spike Base (Res)** bearish ones (both hidden is NinjaTrader's Show Late Spike off). **Globex Start Time** is a Time input, so the overnight count can start at any minute (NinjaTrader takes whole hours). An IB label on the right stays at the line's end once the line stops at the Stop Time (NinjaTrader keeps it at the current bar, so overnight it drifts away from its line; TradingView stops it with the line); with **Extend IB Levels** Right or Both the line runs to the chart's right edge and its label stays at the current bar, as in NinjaTrader. The 80% Rule fill is a translucent range (the bars show through) over each run of bars from one bar's center to the next bar's center (NinjaTrader shades each bar from half a bar before its center to half a bar after: the same width, half a bar to the right), its transparency an input (**80% Rule Fill Transparency**, 93), the active and confirmed colors the **80% Rule Fill** subgraph's primary and secondary colors. The single prints are translucent ranges too (the bars show through), each block from the bar before the one that first traded it (NinjaTrader's start) to 30 minutes past the current bar (to the nearest bar), but not past the end of the chart's Session Times: NinjaTrader's time axis has no bars in the break after the session, so after the close and over the weekend its single prints end at the session's last bar (an early close the Session Times don't hold keeps the 30 minutes); their transparency an input (**Single Print Transparency**, 90: NinjaTrader's 10% orange), their color the **Single Print** subgraph's; hidden (fill and borders), they are still tracked and count toward the 2,000 structures. Their borders (NinjaTrader's Border Width 0 is the **Single Print Border** subgraph Hidden, the default) outline each block as NinjaTrader does; a part of a block before the first loaded bar is blended over the chart background. **Poor High** and **Poor Low** each have a subgraph (both hidden is NinjaTrader's Show Poor Highs/Lows off), and so does each naked POC kind (a hidden kind is not tracked, as NinjaTrader's Show switch). The RTH open (dOpen) and the weekly open each have a label size input with Off (NinjaTrader's one Opens Show Labels switch serves both). Each past day's dOpen line is kept like its IB and pd lines, so showing **dOpen** shows the past days at once. The prior week's and month's high and low, as in NinjaTrader, need the whole prior week and month loaded, and a week whose first bar is not Sunday 17:00 (a Monday holiday) has no weekly open. An IB line extended both ways (**Extend IB Levels** Both) keeps the IB's label switch, and Force on Top's **Daily Levels (All)** lifts only the daily levels: NinjaTrader puts every line extended both ways in the daily levels' label group, so its IB labels then follow the levels' Show Labels and rise with them. The forming bar's profiles and alerts use the 1-minute bar as it stands at each chart update (NinjaTrader updates its primary series before its 1-minute series on each tick, so its preview reads the minutes one tick late). Prices are snapped to the tick and shown in the chart's price format. Daily levels: Sierra Chart's text inputs are single-line, so the paste box is edited in a multi-line editor from the chart's right-click menu (**Tatanka AMT: Edit Levels...**) or filled from the clipboard (**Tatanka AMT: Paste Levels from Clipboard**); the text is read exactly as NinjaTrader reads it, with the same messages and .NET's number rules. The levels file is re-read at most every 5 seconds while the chart is live, and its last-good cache is kept in Sierra Chart's `Data\Tatanka\LevelsCache` folder (NinjaTrader keeps its own under its user folder, so the two platforms don't share caches). Each level takes its kind's subgraph (**PIVOT**, **RES** or **SUPP**: color, width, style, label text color, and the label text plus the level's number, so a renamed RES subgraph renames RES1, RES2...); Hidden hides that kind's lines and keeps their labels and zones (NinjaTrader's one Show Level Lines switch hides all three kinds). A flipped level takes the other side's color and "FLIPPED " before its name, as in NinjaTrader. The zone borders have the **Level Zone Border** subgraph (Hidden = no borders; the width is editable, NinjaTrader's is 1; the color is each level's). The zones are translucent ranges from the chart's first bar to its right edge. A **Dotted** line (the levels' default, also IB Midpoint and the poor highs/lows) is drawn as dots: NinjaTrader's Dotted style draws nothing on its charts (Direct2D's dots have no length with the flat line ends NinjaTrader uses), so there a dotted level shows only its label and zone; choose Hidden on the subgraph for that look. Discord: Sierra Chart makes the request (`sc.MakeHTTPPOSTRequest`, its own connection and certificate checks) and gives the study only Discord's answer, not the HTTP status, so the answer decides: the posted message (delivered), a rate limit (later messages wait `retry_after`, 1 to 60 seconds, and the message is sent once more), Discord's error code ("Discord error 10015" where NinjaTrader says "HTTP 404"), Sierra Chart's own "ERROR" (an HTTP or connection error it doesn't tell apart; later messages wait 2 seconds in case it was a rate limit), or no answer within 15 seconds (a connection error; NinjaTrader gives up after 5). Sierra Chart runs one request at a time, so after those 15 seconds the next message still waits for Sierra Chart's answer, at most a minute. A failed message is never resent, as in NinjaTrader. The study posts to the webhook's Discord API version 10 address (`https://discord.com/api/v10/webhooks/...`, the same webhook) whatever form of the URL was pasted: Discord answers the usual unversioned URL with its old default version, whose rate-limit answer counts `retry_after` in milliseconds (NinjaTrader reads the HTTP header, which is in seconds). The message is `[symbol] alert | close price | time CT` with Sierra Chart's symbol (NinjaTrader's full instrument name) and the time of the latest trade (NinjaTrader stamps the forming bar's end, so a 09:31 alert on a 5-minute chart said 09:35:00); a message cut at 1,900 characters never splits an emoji in two. Alerts: Sierra Chart's alert sound list (**Alert Sound**: No Alert = none, No Sound = the Alerts Log only; Discord follows its own switch); the levels are checked once per chart update with the latest price (NinjaTrader checks every tick), so a cross that reverses within one update interval is missed; a full recalculation or a reload never repeats an alert already given on the forming bar (NinjaTrader's reload can). Editing colors, transparencies, label settings, the dashboard or the profile's width, alignment and offset applies at once without recalculating. **Hide Study** draws nothing but keeps the alerts running.
